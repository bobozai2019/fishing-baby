## 1. 项目目标

在 Godot 4.7 中完成一个可重复游玩的 2D 横屏单关卡：抓钩自动摆动，玩家使用鼠标左键或空格键出钩，捕获鱼类、生物或杂物并回收计分，在 90 秒内达到 1200 分即获胜。Demo 必须可在 Windows 和 Web 浏览器中运行，一局结束后可立即重开，不读写任何存档。

## 2. 前置假设与成功口径

1. 基准分辨率为 1920×1080，保持横屏，宽高比变化时不拉伸主体。
2. 关卡固定摆放当前 5 种鱼、2 种生物和 5 种拾取物，确保每类运行时资源均出现。
3. “包含当前资源”指游戏运行时素材集；切片 cell、预览图、源文件和同一背景的备选组装方式不要求同时出现。
4. 鱼类持续游动并在边界折返；海底物件固定；水母低速漂动。
5. 得分在物件被拉回船上时结算，不在碰撞瞬间结算。
6. 参考项目只用于提取抓钩状态机、捕获物定义、绘制/逻辑分层思路；不复制 React/Canvas 代码。
7. 默认现有美术足以完成 MVP；音频与新位图不是验收门禁。

成功标准：
- 可完整走通“开始→摆动→出钩→碰撞→回收→计分→胜/负→重开”。
- 连续进行 20 次出钩不出现卡死、重复结算或多物件同时挂钩。
- Windows 发布包和 Web 发布包均可进入、完成、重开关卡。

- Gate 1 契约冻结后，T02、T03、T04 可并行，但分别只修改场景/UI、抓钩、抓取物所属路径。
- T03 和 T04 都不得独自改动已冻结的信号字段；若契约必须改变，先由主 agent 更新 ADR 和 Gate 1 状态。
- T05 开始后暂停 T02/T03/T04 对共享场景的并行写入。
- 当前默认由主 agent 串行执行；未经用户明确授权不启动 subagent。

## 10. 验收与证据计划

1. 静态检查：场景可解析，脚本无 parse error，资源路径存在。
2. 逻辑测试：抓钩合法/非法迁移、单次计分、胜/负、重开重置。
3. 场景验证：headless 加载 `main.tscn`，所有必需节点与 12 个类型 ID 存在。
4. 视觉验收：1920×1080、1280×720 截图，检查 HUD、水面、船、钩和目标的可读性。
5. 发布验收：Windows 实机流程 + Web Chrome/Edge E2E。
6. 所有实际结果只写入 `验收/`和 `执行状态.md`，不回写到契约文件。
