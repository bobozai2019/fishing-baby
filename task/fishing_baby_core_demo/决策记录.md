# Fishing Baby 核心 Demo 决策记录

## ADR-001：首版只实现单关卡核心闭环

- 日期：2026-08-07
- 状态：accepted
- 背景：用户选择“可玩核心 Demo”和一个简单关卡。
- 决策：90 秒、1200 分、单抓钩、一关、胜负与重开。
- 影响：商店、升级、成就、宠物、天气等全部从 MVP 移除。

## ADR-002：Windows 与 Web 共用 GL Compatibility

- 日期：2026-08-07
- 状态：accepted
- 背景：当前 `project.godot` 使用 Forward Plus，但 Web 是 MVP 平台。
- 决策：本 Demo 使用 GL Compatibility，不引入 Forward+ 专属效果。
- 影响：T01 修改项目渲染配置；T07 同时验证 Windows/Web。

## ADR-003：使用 Godot 场景 + Resource + 信号边界

- 日期：2026-08-07
- 状态：accepted
- 背景：参考项目将游戏循环、数据和 UI 分层，当前项目规范要求场景优先固化。
- 决策：使用 `.tscn` 固化布局和资源绑定，`Resource` 保存可调数据，信号连接 Hook/Catchable/Round/HUD。
- 影响：不在 `_ready()` 动态搭建整棵静态 UI 或关卡节点，不引入全局存档单例。

## ADR-004：关卡采用手工固定摆放

- 日期：2026-08-07
- 状态：accepted
- 背景：MVP 要求当前所有捕获类资源都出现，且需要稳定验收。
- 决策：12 类目标以场景实例手工摆放，鱼类只在运行时执行移动与边界折返。
- 影响：MVP 不实现随机生成器；重开通过重置/重载关卡恢复初始状态。

## ADR-005：优先复用当前美术

- 日期：2026-08-07
- 状态：accepted
- 背景：现有美术已覆盖背景、主角/船、抓钩、鱼、生物、杂物和 HUD。
- 决策：MVP 不预先生成新位图；用 Tween、`Line2D`、颜色和文字补足反馈。
- 影响：只有 Gate 2 视觉验收证明存在阻塞级缺口时，才依 `resources/PROMPTS.md` 新增美术。

## ADR-006：当前 Web 模板使用隔离头辅助服务

- 日期：2026-08-07
- 状态：accepted
- 背景：`4.7.beta.custom_build` 导出配置已写入 `threads=false`，但配套 nothreads 模板仍在普通 HTTP 下因 `SharedArrayBuffer` worker 卡住；Godot 官方文档明确单线程模板正常不应有此要求。
- 决策：保留单线程导出配置，提供 `tools/serve_web.py` 添加 COOP/COEP 响应头完成当前构建验收。
- 影响：Web 产物可交付，但换用修正后的正式 4.7 模板后应复测普通静态服务器并删除此兼容要求。

## ADR-007：捆绑 Noto Sans CJK SC

- 日期：2026-08-07
- 状态：accepted
- 背景：桌面默认字体可显示中文，Web 默认字体会显示方框。
- 决策：在 `resources/fonts/` 捆绑 OFL 1.1 的 `NotoSansCJKsc-Regular.otf`，HUD、提示、结果与反馈统一使用。
- 影响：Web PCK 增大约 14 MB，但 Windows/Web 中文可读性一致。
