# [已完成] 游戏模式与单人角色选择执行总纲

来源：

- 用户需求：进入游戏后先选“单人/多人”；单人再从小孩列表中选择一名；当前两名角色，后续可扩展。
- `docs/architecture/当前技术架构.md`
- `docs/design/核心玩法设计文档.md`

## 1. 项目目标

在现有本地双人核心玩法前增加模式选择流程。单人模式选择一名角色后，只启用一套船、抓钩、输入、计分和个人道具显示；多人模式保持当前两人同屏竞技。角色使用 Resource 数据定义，新增角色不需要修改选择界面逻辑或复制玩法代码。

## 3. 假设与产品口径

1. “多人”是现有的本地双人同屏，不包含联网、房间或匹配。
2. 单人选择角色只改变角色外观与会话参与者，不改变抓钩参数、分值或关卡难度。
3. 单人统一使用逻辑玩家 `P1`，所选角色装配到主船；`P2` 船、抓钩、分数和个人效果 UI 隐藏/禁用。
4. 多人 MVP 继续使用男孩 P1、女孩 P2，不增加多人角色选择。
5. “再来一局”保留本次模式与角色；结算界面另提供“返回模式选择”。

## 8. 执行 DAG 与并发窗口

```text
T00 基线与契约冻结
  ├─> T01 会话配置与角色数据
  │      └─> T02 模式/角色选择 UI
  └─> T03 单人参与者与玩法规则
             └─> T04 主流程集成与返回/重开
T02 + T04 ──> T05 自动化、视觉、文档与最终验收
```

安全并发：T02 可在 T01 的角色字段和选择信号冻结后，与 T03 并行。禁止多个执行者同时修改 `scripts/main.gd`、`scenes/main.tscn` 或会话状态契约。
