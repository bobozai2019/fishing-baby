# [已完成] Godot Web 纯 2D 裁剪与 Brotli 包体测试执行总纲

来源：

- 用户要求：为当前 Godot 4.7.1 项目制作自定义纯 2D Web 导出模板，接入 Brotli，并测试最终 Web 包体。
- 当前构建入口：`build.bat`
- 当前正式导出目录：`build/web_playtest/`
- 当前基线（仅作计划输入，Gate 0 必须重跑取证）：原始目录约 45.34 MiB；`index.wasm` 约 37.68 MiB；`index.pck` 约 7.34 MiB；Brotli 核心传输表示约 16.1 MiB。

任务目标：

- 使用与编辑器完全匹配的干净 Godot 4.7.1 stable 源码，编译项目专用纯 2D Web release/E2E 模板。
- 保留中文、GDScript、2D 渲染、2D 物理、GL Compatibility、基础 UI、JavaScriptBridge E2E 能力，裁掉确认未使用的 3D、3D 物理和可选模块。
- 将模板选择、字体子集、Web 导出、Brotli、包体清单、服务端响应验证纳入可重复构建链。
- 以可复现报告同时给出原始目录、上传制品和浏览器传输三种口径；Brotli 口径必须低于 25 MiB，原始目录是否作为硬门禁由 Gate 0 根据目标平台规则冻结。

## 2. MVP 边界

### 必须完成

1. 冻结 25 MB 的目标平台统计口径。
2. 使用干净且可追溯的 Godot 4.7.1 stable 源码，不使用现有脏 `D:/godot/godot_master`。
3. 生成并冻结纯 2D 引擎功能清单与 `.gdbuild`/SCons 参数。
4. 编译 Web `template_release`；若完整 E2E 需要不同 JS 能力，则同时编译 E2E 变体。
5. `build.bat` 使用自定义模板导出到 `build/web_playtest/`，构建前仍只清空这一固定目录。
6. 对实际传输文件生成 Brotli 表示和字段级体积清单。
7. 验证 Brotli 响应头、MIME、WASM 启动、中文、双钩、碰撞、波次、道具、结算与视口。
8. Brotli 传输总量小于 25 MiB，并记录原始总量；原始总量门禁按 Gate 0 结论执行。
9. 提供恢复官方模板的明确回滚方式。

### 占位但不验收

1. Windows 自定义模板使用同一裁剪配置的可行性说明。
2. CDN/对象存储厂商的生产配置样例入口。

### vNext

1. 继续降采样 1024/1254 像素运行贴图。
2. 自动上传 CDN、缓存失效与版本发布。
3. 多语言字符集按 locale 分包。

### 明确不做

1. 迁移到 Cocos Creator 或 Unity。
2. 修改玩法、数值、美术风格或输入规则。
3. 为减包删除中文、2D 物理或正式 UI。
4. 修改或清理 `D:/godot/godot_master` 的既有用户改动。
5. 将只在编辑器中禁用功能误当作运行时引擎裁剪。

## 6. 谨慎并发窗口

允许并发（仅在后续明确委派时）：

1. Gate 0 后，T01 只操作 `tools/` 下新源码，T02 只写裁剪清单和契约，可并发。
2. Gate 2 后，可并行准备 Brotli 工具与黑盒验收清单，但不得同时改 `build.bat`。
3. 最终功能 E2E 与包体统计可并发读取同一冻结产物，禁止边测边重建。

禁止并发：

1. 多任务同时修改 `export_presets.cfg`、`build.bat` 或 `tools/serve_web.py`。
2. 模块裁剪清单未冻结时并发编译多个不可追溯配置。
3. 对同一 `build/web_playtest/` 边构建边验收。
