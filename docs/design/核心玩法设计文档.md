# Fishing Baby 核心玩法设计文档

版本：1.3  
日期：2026-08-10  
适用范围：当前单关卡核心 Demo

## 1. 设计目标

Fishing Baby 是一款支持横屏与竖屏的 2D 休闲钓鱼游戏，核心体验参考“黄金矿工”：玩家观察自动摆动的抓钩，在合适角度按下单键出钩，捕获水下鱼类、生物或杂物并回收到船上得分。

首版设计目标是让玩家无需教程即可在一分钟内理解操作，并在一局内体验观察、判断、发射、命中、回收和得分的完整节奏。

核心体验关键词：

- 单键操作，容易上手。
- 摆角与时机决定命中结果。
- 不同目标具有明显的价值和重量差异。
- 90 秒内持续做出“稳妥小收益”与“瞄准高价值目标”的选择。
- 命中、空钩、回收和结算均提供清晰反馈。

## 2. 核心玩法循环

```text
观察抓钩摆动
    ↓
选择目标与发射时机
    ↓
抓钩向当前角度伸出
    ├─ 未命中 → 到达最大长度 → 空钩回收
    └─ 命中   → 目标挂钩 → 按重量减速回收
                                      ↓
                              到达船边后结算分数
                                      ↓
                              继续摆动并选择目标
```

得分只在处于 `HOOKED` 状态的目标回收到船边后结算。空钩或丢失有效挂钩目标的回收不得产生分数。碰撞成立时，目标必须当帧显示在钩爪中心；碰撞瞬间只表示“抓住”，避免玩家在目标仍位于水下时误以为本次行动已经完成。

## 3. 单局规则

| 项目 | 规则 |
|---|---|
| 关卡数量 | 1 个固定摆放关卡 |
| 游戏模式 | 单人或本地双人，启动后先选择 |
| 单人角色 | 从角色目录选择一名；当前为男孩、女孩，角色能力相同 |
| 单局时长 | 90 秒 |
| 获胜目标 | 单人或任一多人玩家达到 1800 分立即获胜 |
| 超时结算 | 单人未达目标则失败；多人高分玩家获胜，同分为平局 |
| 抓钩数量 | 单人 1 个；多人 P1/P2 各 1 个，可同时行动 |
| 携带上限 | 每次出钩最多捕获 1 个目标 |
| 计分时机 | 目标送达船边时 |
| 重开 | 胜负结算后立即重开，恢复全部目标和初始状态 |
| 持久化 | 不保存分数、关卡或玩家状态 |

目标按已用时间 0、30、60 秒分三波追加出现，旧波未捕获目标继续保留。

## 4. 操作设计

| 状态 | 键盘 | 鼠标/触控 | 结果 |
|---|---|---|---|
| 模式选择 | 方向键/Tab + Enter | 点击/触控单人或多人 | 单人进入角色选择，多人进入准备 |
| 单人角色选择 | 方向键/Tab + Enter | 点击/触控角色卡 | 所选角色进入主船并进入准备 |
| 准备 | 空格或 Enter | 点击开始按钮 | 开始倒计时 |
| 单人游戏中且抓钩摆动 | Q 或空格 | 任意水域点击/触控 | 所选角色按当前角度出钩 |
| 多人游戏中且抓钩摆动 | P1：Q；P2：P | 左右水域分区点击/触控 | 对应玩家按当前角度出钩 |
| 抓钩伸出或回收 | 任意重复输入 | 任意重复点击 | 忽略，不打断当前动作 |
| 胜利或失败 | 空格或 Enter | 点击“再来一局” | 重置关卡并回到准备状态 |

同一物理帧内的多个等价输入只触发一次状态迁移，防止一次点击同时开始回合并发射抓钩。

## 5. 抓钩设计

抓钩在船上起点附近以 `-65°` 至 `65°` 自动往复摆动。玩家不能手动控制摆动方向，只能决定何时发射。

| 参数 | 当前值 | 设计作用 |
|---|---:|---|
| 摆动速度 | 55°/秒 | 给玩家足够观察时间，同时保持行动节奏 |
| 初始绳长 | 72 px | 让抓钩与船体保持清晰间距 |
| 最大绳长 | 880 px | 覆盖主要水下区域，但保留角度选择 |
| 伸出速度 | 650 px/秒 | 发射反馈迅速 |
| 基础回收速度 | 420 px/秒 | 空钩等待较短，重物差异可感知 |

抓钩贴图顶部圆环是绳索连接点。贴图中心与碰撞体必须沿当前绳方向偏移，使竖直和斜角状态下绳索都保持连接，不得出现绳子穿过抓钩或与挂点分离。

## 6. 可捕获目标

关卡固定放置 16 个计分目标和 3 个即时道具，分三波出现。原有 12 类目标保持分值，新增河豚 180、海马 240、乌贼 360、海龟 500。

三类道具触碰后立即消耗且不打断伸钩：涡轮卷线器令拾取者出/收钩速度 ×1.75，金色巨钩令拾取者钩子尺寸 ×1.60，蓝色冰晶令全局水生物停止自主移动；持续时间均为 5 秒，同类刷新时长但不叠加强度。

| 目标 | 分类 | 分值 | 重量 | 行为 |
|---|---|---:|---:|---|
| 小蓝鱼 | 鱼 | 120 | 0.85 | 快速水平游动 |
| 绿色杂鱼 | 鱼 | 90 | 1.00 | 水平游动 |
| 黄色条纹鱼 | 鱼 | 180 | 1.15 | 水平游动 |
| 紫色巨鱼 | 鱼 | 420 | 1.80 | 缓慢水平游动 |
| 橙红稀有鱼 | 鱼 | 600 | 1.35 | 快速水平游动 |
| 螃蟹 | 生物 | 150 | 1.20 | 海床静止 |
| 水母 | 生物 | 220 | 1.10 | 缓慢漂动 |
| 宝箱 | 宝物 | 500 | 2.20 | 海床静止 |
| 珍珠贝 | 宝物 | 300 | 1.20 | 海床静止 |
| 旧靴子 | 杂物 | 20 | 1.60 | 海床静止 |
| 轮胎 | 杂物 | 30 | 2.00 | 海床静止 |
| 罐头 | 杂物 | 10 | 1.30 | 海床静止 |

重量通过以下关系影响回收速度：

```text
实际回收速度 = 基础回收速度 ÷ 重量倍率
```

高价值目标通常更重或更难瞄准；垃圾价值低且可能拖慢回收，用于制造风险和失误成本。

## 7. 关卡布局

画面分为天空与船、水面、水下活动区、海床四个层次：

- 船位于画面上方中央，吊机挂点和抓钩始终清晰可见。
- 船身与角色头部分层组合；男孩和女孩使用独立头部资源，共用同一船只场景结构。
- 鱼类分布在不同深度和角度，并持续游动。
- 水母位于中层，以漂动形成动态障碍和机会。
- 宝箱、珍珠贝、螃蟹和杂物位于海床附近。
- 高价值目标不会全部集中在同一角度，玩家必须等待不同摆角。
- 目标初始位置不重叠，不与船体或水面相交。

世界以 1920×1080 为横屏基准；竖屏保持设计宽度并延长水下区域，海洋底色使用九宫格拉伸，沙床固定在视口底部。HUD 使用独立画布层，鱼钩在任意摆角下都以当前沙床顶线为最大下放边界。

## 8. 信息与反馈

### HUD

- 单人左上角显示“角色名：当前分数 / 目标分数”，不显示 P2。
- 多人左上角显示 P1/P2 当前分数与目标分数。
- 右上角显示剩余秒数。
- 准备面板说明开始方式和出钩操作。
- 结算面板显示胜负、最终分数和重开按钮。
- “再来一局”保留模式和角色；“返回模式选择”清空当前选择。
- TopBar 下方按 P1 / 全局 / P2 显示加速、巨钩与冰冻的剩余整秒数。

### 行为反馈

| 事件 | 反馈 |
|---|---|
| 发射 | 绳索沿当前摆角快速延伸 |
| 命中 | 目标当帧吸附到钩爪中心，显示“抓住了！”，关闭目标碰撞 |
| 鱼类被抓 | 切换 caught 贴图并轻微挣扎摆动 |
| 重物回收 | 回收速度明显降低 |
| 得分 | 船边显示对应的正分飘字，HUD 更新 |
| 空钩 | 显示“没抓到，再试一次！” |
| 胜利 | 暗化背景并显示“大丰收！” |
| 失败 | 暗化背景并显示失败文案 |

所有中文界面统一使用项目内置的 Noto Sans CJK SC，避免 Web 平台依赖系统字体而出现方框字符。

命中反馈、挂钩画面和最终计分必须保持一致：玩家没有看到目标挂在钩爪上时，本次回收不能显示得分或更新 HUD。

## 9. 视觉方向

- 美式卡通风，使用粗深色轮廓和高饱和色块。
- 角色和鱼类采用夸张比例与表情，保持轻松幽默。
- 船体使用 `boat_body.png`，角色头部分别使用 `boy_head.png` 和 `girl_head.png`；头部应与船员身体颈部对齐，不使用旧的整船人物合成图。
- 不使用写实光照、Bloom、复杂粒子或影响 Web 性能的效果。
- 绳索使用 `Line2D` 绘制，不使用位图绳索。
- 抓钩和目标必须在背景上保持清晰剪影。
- HUD 使用深蓝底、金色边框和高对比文字，与海洋背景区分。

## 10. 难度与节奏

单局总目标分低于场上全部目标总分，玩家不需要清空关卡即可获胜。设计鼓励以下三种策略：

1. 优先捕获稀有鱼和宝箱，以较少次数快速达标。
2. 连续捕获中等价值鱼类和生物，降低瞄准风险。
3. 在高价值目标角度不合适时等待，不为低价值重物浪费时间。

当前计分总量为 3920，目标为 1800。三波分别在已用时间 0、30、60 秒出现，玩家需要权衡早期稳定得分与等待后续高价值目标。

## 11. 平台设计

- 目标平台：Windows 与 Web。
- 渲染器：GL Compatibility。
- 基准分辨率：1920×1080。
- 最低验收视口：1280×720。
- Web 附加验收视口：1365×768。
- Web 竖屏验收视口：390×844、768×1024。
- 鼠标、键盘和触控共享同一玩法状态机。

当前定制 4.7 beta Web 模板需要由 `tools/serve_web.py` 提供跨源隔离响应头。该要求属于构建环境兼容措施，不改变玩法设计。

## 12. 首版范围外

以下内容不属于核心 Demo：

- 商店、升级、装备和背包。
- 成就、任务和排行榜。
- 宠物、装扮、天气和日夜变化。
- 商店、背包、库存式道具、连击和技能树。
- 多关卡、随机生成和无尽模式。
- 存档、账号、云同步和后端服务。
- 广告、内购及移动端发布。
- 完整音乐和音效系统。
- 在线多人和 AI 对手。
- 多人分别选择角色及重复角色规则。
- 角色专属数值、技能、解锁和存档。

后续版本如扩展上述内容，应保持“观察摆角—单键出钩—重量回收—船边结算”的核心循环不变。
